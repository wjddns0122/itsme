# 03. 화면 명세

> 디자이너(팀원 B)와 개발이 함께 보는 문서. Figma 프레임 이름은 화면 ID와 같게 짓는다 (`P-03 분실 신고`).
> 문구는 이 문서가 기준이다. 바꾸려면 이 문서를 고친다.

---

## 1. 공통 디자인 규칙

| 항목 | 규칙 |
|---|---|
| 기준 폭 | 분실자 화면 360px (모바일), 관리자 화면 1024px (태블릿 가로·노트북). A-03은 360px도 지원 |
| 터치 영역 | 44px 이상 |
| 글자 대비 | 4.5:1 이상 |
| 디자인 토큰 | 팀원 A가 Day 1 저녁에 확정: 주색, 보조색, 성공/경고/위험색, 폰트, 모서리 둥글기 |
| 컴포넌트 | shadcn/ui 기반. 새 컴포넌트가 필요하면 B가 Figma에 먼저 그린다 |
| 문체 | "~해요"체. 짧게. 기술 용어(AI, 임베딩, 점수) 노출 최소화 |
| 상태 | 모든 화면은 **기본 / 빈 상태 / 로딩 / 에러** 네 가지를 그린다 |

상태 배지 (색은 토큰 확정 후 지정)

| 값 | 표시 문구 |
|---|---|
| `stored` | 보관 중 |
| `claimed` | 확인 중 |
| `returned` | 반환 완료 |
| `transferred` | 경찰 이관 |
| `disposed` | 처리 완료 |
| 매칭 후보 있음 | 후보 n |
| 유사도 0.70 이상 | 유사도 높음 |
| 유사도 0.45~0.70 | 유사도 보통 |

## 3. 분실자 화면

### P-01 시설 찾기 (홈)

- 목적: 어디서 잃어버렸는지 아는 사람은 시설을 바로 찾고, QR 없이도(집에 돌아가서도) 신고를 시작한다.
- 구성
  - 제목: "어디에서 물건을 잃어버리셨나요?" / 보조: "방문했던 곳을 검색해 주세요."
  - 검색창 자리표시: "시설 이름이나 지역 (예: 평창 스키장, 노원구)"
  - 종류 칩: 전체 / 스키장 / 숙박·리조트 / 대학교 / 축제·행사 / 카페·식당
  - 결과 목록: 시설 이름, 지역, 종류 아이콘, > (P-02로)
  - 검색 전 첫 화면: 이 기기에서 최근 본 시설, 지역별 참여 시설 몇 곳
  - 하단 안내: "잇츠미를 쓰는 시설의 습득물만 찾을 수 있어요."
- 결과 없음: "찾는 곳이 아직 잇츠미를 쓰지 않아요. 시설에 직접 문의하거나 경찰청 LOST112에서 찾아보세요." + LOST112 주소 + (P1) [지역으로 찾기]
- (P1) 여러 시설 고르기: 체크해서 [선택한 n곳에 한 번에 신고] → P-08
- 로딩: 시설 줄 모양 3개 (스켈레톤). 에러: "시설 목록을 불러오지 못했어요. 다시 시도해 주세요." + [다시 시도]
- 검색 상태는 주소에 둔다 (`/?q=평창&type=ski_resort`). 링크로 공유하거나 뒤로 가기를 해도 같은 결과가 나온다.
- 시안과 데모의 시설 이름은 예시 이름으로 쓴다 (ADR-028).

### P-02 시설 페이지

- 목적: 검색·홈페이지 링크·검색엔진·QR 어디로 들어와도 같은 시설 페이지에서 시작한다. QR로 들어오면 시설 선택이 이미 끝난 상태다.
- 구성
  - 시설 이름, 지역, 종류, 소개 한 줄, 로고(있으면)
  - 큰 버튼 2개: **"물건을 잃어버렸어요"** → P-03 / **"물건을 주웠어요"** → P-06
  - 안내: "이미 신고하셨다면 신고 링크에서 진행 상황을 볼 수 있어요."
  - 안내데스크 연락처, 운영 시간
  - 하단: "잇츠미로 운영돼요"
- 검색엔진 노출: 페이지 제목 "{시설 이름} 분실물 찾기 | 잇츠미"와 설명 문구. 시설이 동의한 경우(`is_listed`)에만 노출 (Q19)
- 에러: 없는 slug → "시설을 찾을 수 없어요. 시설 이름으로 다시 검색해 주세요." + [시설 찾기]
- 불러오기 실패: "시설 정보를 불러오지 못했어요. 다시 시도해 주세요." + [다시 시도]
- 정보가 적은 시설: 비어 있는 소개·안내데스크·운영 시간 줄은 숨긴다. 안내데스크 위치가 없으면 "연락처" 줄만
- 검색엔진 설명 문구: 소개 한 줄, 없으면 "{시설 이름}에서 잃어버린 물건을 신고하고, 주운 물건을 맡기는 곳을 확인할 수 있어요."
- 이 페이지를 열면 P-01 "최근 본 시설"에 이 기기에서만 저장한다

### P-03 분실 신고

- 목적: 60초 안에 신고. 상단에 진행 표시 `1/3`.
- 상단 안내: "기억나는 것만 적어주세요. 모르는 건 넘어가도 괜찮아요."
- **1단계 — 무엇을 잃어버렸나요?**
  - 분류 칩: 휴대폰, 이어폰, 지갑·카드, 가방, 옷·장갑, 고글·헬멧, 안경, 열쇠, 기타
  - 색상 칩 (여러 개 선택) + **"잘 모르겠어요"**
  - 브랜드: [기억나요 → 입력칸] / **"잘 모르겠어요"**
  - 자유 서술 (선택). 자리표시: "예) 검은색 무선 이어폰인데 케이스에 은색 키링이 달려 있어요."
  - 물건이 나온 사진 (선택): "여행 중 찍은 사진에 물건이 나왔다면 올려주세요. 물건 모양만 참고해요." 최대 3장
  - 분류나 설명 중 하나만 있어도 다음 단계로 갈 수 있다.
- **2단계 — 언제, 어디서 잃어버렸나요?**
  - 날짜 범위 (시작~종료, 기본값 오늘~오늘). 빠른 선택: 오늘 / 어제 / 최근 3일
  - 마지막으로 쓴 시간대 칩: 오전 / 점심 / 오후 / 저녁 / **모름**
  - 구역 선택: 시설 구역 목록 + "잘 모르겠어요"
  - 체크: "빌린 물건이에요 (렌탈 장비 등)"
- **3단계 — 연락받을 곳**
  - 이메일, 전화번호 (둘 중 하나 이상 필수). 이름 (선택)
  - 나만 아는 특징 (선택): "케이스 안쪽 스티커, 이니셜처럼 남은 모르는 특징을 적어주세요. 관리자만 볼 수 있어요."
  - 동의 체크 (필수): "분실물 반환을 위해 연락처를 수집해요. 신고가 끝나고 30일 뒤 삭제해요." + 전문 보기
  - 버튼: **"신고하기"**
- 검증 에러 문구
  - 분류도 설명도 없음: "어떤 물건인지 분류를 고르거나 한 줄이라도 적어주세요."
  - 연락처 없음: "이메일이나 전화번호 중 하나는 꼭 필요해요."
  - 동의 안 함: "동의해야 신고할 수 있어요."
- 로딩: 버튼에 스피너, 중복 제출 막기.
- 추가 검증 문구: 이메일 형식 "이메일 주소를 다시 확인해 주세요." / 전화번호 형식 "전화번호를 다시 확인해 주세요." / 날짜 "날짜를 다시 확인해 주세요. 오늘 이후나 1년보다 오래된 날짜는 고를 수 없어요." / 저장 실패 "신고를 보내지 못했어요. 잠시 후 다시 시도해 주세요."
- 동의 전문(전문 보기): 수집 항목(이메일, 전화번호, 이름·나만 아는 특징은 선택), 목적(찾았을 때 연락, 주인 확인), 보관 기간(신고가 끝나고 30일 뒤 삭제), 볼 수 있는 사람(신고한 시설 관리자), 동의하지 않으면 신고할 수 없음. 법적 문구 검토는 Q21
- 상단 바 오른쪽에 시설 이름. 검색엔진에는 노출하지 않는다 (noindex)

### P-04 신고 현황·후보

- 목적: 신고 상태와 후보를 확인. 로그인 없이 링크로 접근.
- 첫 진입(`?new=1`) 배너: **"신고했어요! 이 페이지 주소를 저장해 두세요."** + [링크 복사] (이메일 입력 시: "이메일로도 보냈어요.") 아래 한 줄: "진행 상황은 전화하지 않고 이 페이지에서 확인할 수 있어요."
- 구성
  - 내 신고 요약: 설명 첫 줄, 분실 기간, 구역, 상태 배지
  - 후보 영역
    - 분석 중: "비슷한 물건을 찾고 있어요…" (5초마다 새로고침)
    - 후보 없음: "아직 비슷한 물건이 없어요. 새로 들어오면 알려드릴게요."
    - 후보 카드 (최대 5개): 분류 아이콘, 공개 설명, 습득일, 구역, 유사도 배지, 버튼 [내 물건 같아요] [아니에요]
    - 정보 충족도가 낮으면 후보 위에 한 줄: "알려주신 정보가 적어서 비슷한 물건을 넓게 보여드려요. 특징을 더 적으면 정확해져요." + [신고 내용 보완하기]
  - 확인 요청 중: "관리자가 확인하고 있어요. 보통 하루 안에 연락드려요."
  - 추가 증빙 요청: 관리자가 적은 요청 내용 + 사진·답변 입력 + [보내기]. 문구: "확인을 위해 조금 더 알려주세요."
  - 승인됨: 수령 안내 카드 (장소, 운영 시간, 지참물, 연락처)
  - 하단: [신고 취소]
- 금지: 습득물 사진, 비공개 특징, 점수 숫자를 보여주지 않는다.
- 에러: 없는 토큰 → "신고를 찾을 수 없어요." + [시설 찾기]
- 신고 상태 배지: 찾는 중(`open`) / 확인 중(`claimed`) / 찾았어요(`resolved`) / 취소됨(`closed`)
- 대여 물품이면 첫 진입 배너에 "빌린 물건이라면 빌린 곳(렌탈샵)에도 알려주세요."
- 승인됨 위에 말풍선 "찾았어요!" (Figma 제안 문구)
- [신고 취소]는 같은 화면에서 한 번 더 묻는다: "신고를 취소할까요? 취소하면 더 이상 비슷한 물건을 찾지 않아요." [취소할게요] [아니요]. 취소 뒤 "신고를 취소했어요."
- 이 페이지는 비밀 링크라 검색엔진에 노출하지 않고 다른 사이트로 주소를 넘기지 않는다 (noindex, no-referrer)

### P-05 소유권 확인 요청

- 목적: 진짜 주인인지 관리자가 판단할 정보를 받는다. 정답을 알려주지 않는 질문으로 묻는다.
- 구성
  - 상단 안내: "안전한 반환을 위해 물건에 대해 몇 가지 여쭤볼게요. 기억나는 만큼 적어주세요."
  - 선택한 후보 요약 (공개 정보만)
  - **분류별 확인 질문 2~3개** (주관식, 1개 이상 필수). 예: 이어폰 → "겉모습에 다른 것과 구별되는 특징이 있나요?", "케이스에 붙어 있거나 달려 있던 것이 있나요?", "마지막으로 쓴 곳과 시간은 언제인가요?" (질문 목록: `docs/05-ai-matching.md` §9-1)
  - 사진 첨부 (선택): "같은 물건을 들고 찍은 사진, 구매 내역 등"
  - 고가품(휴대폰·노트북 등) 안내: "받으러 오실 때 잠금 해제나 일련번호 확인이 필요해요."
  - 버튼: **"확인 요청하기"**
- 객관식이나 예/아니오 질문을 쓰지 않는다 (정답을 찍을 수 있음).
- 완료 후 P-04로 이동. AI 비교 결과는 보여주지 않는다.
- 이미 진행 중인 요청이 있으면: "이미 확인 중인 요청이 있어요. 결과가 나오면 다시 요청할 수 있어요."
- 같은 물건에 두 번 확인되지 않으면: "이 물건은 더 요청할 수 없어요. 궁금한 점은 시설로 문의해 주세요."

### P-06 습득물 맡기는 방법

- 맡기는 곳(안내데스크 위치), 운영 시간, 연락처, 간단한 지도 이미지(시설이 올린 경우).
- 문구: "주워주셔서 감사해요! 안내데스크에 맡겨주시면 주인에게 돌려드릴게요."
- 줄 이름: 맡기는 곳 / 연락처 / 운영 시간. 정보가 하나도 없으면 "맡기는 곳 정보가 아직 없어요. 시설 직원에게 전해 주세요."
- 아래에 [시설 페이지로]. Figma 시안은 아직 없어 P-02 부품(마스코트, 안내 카드)으로 만든다

### P-07 수령 방법 선택 (P1)

- 승인된 뒤에 보인다. 선택지: 방문 수령(날짜·시간대 예약) / 대리 수령(대리인 이름·관계) / 착불 택배(주소 입력)
- 고가품은 방문 수령만 가능: "휴대폰·노트북은 직접 받으러 오셔야 해요."
- 택배를 고르면: "택배비는 받는 분이 내요. 주소는 반환 후 30일 안에 지워요."

### P-08 여러 시설 한 번에 신고 (P1)

- P-01에서 시설을 여러 곳 고른 뒤 들어온다. 신고 양식은 P-03과 같고, 2단계 구역은 시설마다 따로 고른다 (모르면 "잘 모르겠어요").
- 제출하면 시설마다 신고가 하나씩 만들어지고, 분실자는 신고 링크 하나로 모두 본다.
- 안내: "고른 시설의 관리자에게만 신고 내용이 전달돼요."

## 4. 관리자 화면

공통 레이아웃: 왼쪽 메뉴 (대시보드, 습득물, 확인 요청 n, 분실 신고, 설정), 상단에 시설 이름과 로그아웃. 모바일 폭(768px 미만)에서는 하단 탭, 윗줄에는 잇츠미·시설 이름·로그아웃 아이콘. 디자인: Figma "잇츠미 디자인" 03 관리자 시안 (Sidebar, AdminHeader, TopBar, BottomTabBar).

### A-01 로그인

- 이메일, 비밀번호, [로그인]. 에러: "이메일 또는 비밀번호가 맞지 않아요."
- 요청이 너무 많거나 서버 오류: "잠시 후 다시 시도해 주세요."
- 로그인했지만 연결된 시설이 없는 계정: "이 계정에 연결된 시설이 없어요. 잇츠미 담당자에게 문의해 주세요."
- 로그인 실패 뒤에도 입력한 이메일은 남긴다 (비밀번호는 비운다).

### A-02 대시보드

- KPI 카드 5개: 보관 중 / 확인 요청 대기 / 이번 달 반환 / 이번 달 반환율 / 이번 주 문의
- 할 일 목록: 확인 요청 대기 (→ A-06), 이관 기한 3일 이내 (→ A-05)
- (컷 가능) 최근 7일 습득·반환 막대 차트
- 큰 버튼: **[+ 습득물 등록]** (항상 보이게, 모바일에서는 하단 고정)
- 보조 버튼: [문의 기록] (A-10). 전화를 받으면서 바로 누를 수 있게
- 빈 상태: "아직 등록한 습득물이 없어요. 첫 습득물을 등록해 보세요."

### A-03 습득물 등록 ★ 핵심

- 목적: 15초 안에 등록.
- 상단 토글: **빠른 등록** (연속 촬영). 켜면 사진 → 보관 위치 → 저장만 하고 AI 결과 확인은 건너뛴다. 확신도가 낮거나 민감 물품이면 A-04 "확인 필요" 탭으로 간다.
- [민감 물품] 버튼: 신분증·카드는 AI 분석 없이 분류만 골라 등록한다. 안내: "이 사진은 외부 AI로 보내지 않아요."
- 1단계 — 사진
  - 큰 촬영 영역: [사진 찍기] (모바일 카메라 직접), [앨범에서 선택]. 최대 3장
  - 업로드 후 썸네일 + "AI가 물건을 살펴보고 있어요…" (스켈레톤 양식)
- 2단계 — 확인·수정 (AI가 채운 값, 수정 가능)
  - 분류 (드롭다운), 세부 종류 (텍스트), 색상 (칩 다중 선택), 브랜드 (텍스트, "추정" 라벨)
  - 공개 설명 (여러 줄): 라벨 옆 "분실자에게 보여요"
  - 비공개 특징 (여러 줄): 라벨 옆 자물쇠 아이콘 + "관리자만 봐요. 주인 확인에 써요". 도움말: "일련번호, 각인, 안에 든 물건, 흠집 위치처럼 주인만 알 만한 것을 적어주세요."
  - 민감 물품 스위치 (AI가 켜면 경고 배너: "신분증·카드로 보여요. 사진은 공개되지 않아요.")
  - 습득 일시 (기본값 지금), 습득 구역 (드롭다운), 보관 위치 (텍스트, 직전 값 기본)
  - 버튼: **[저장하고 계속 등록]** / [저장]. 스키장은 하루 최대 100건이라 연속 등록이 기본 동작이다 (사진 → 확인 → 다음 사진)
- AI 실패: 노란 배너 "AI 분석이 안 됐어요. 직접 입력해 주세요." + 빈 양식
- AI가 채운 필드는 옅은 배경색으로 표시, 관리자가 고치면 일반 배경으로 바뀐다.
- 사진 전: "사진을 먼저 올려 주세요. 사진이 없으면 [직접 입력하기]로 시작해요." (사진 없이도 등록할 수 있다)
- 첫 사진을 올리면 바로 분석한다. 분석 뒤에 더한 사진은 저장만 하고 다시 분석하지 않는다.
- 저장하고 계속 등록 뒤: "등록했어요. 다음 물건 사진을 올려 주세요." 보관 위치와 습득 구역은 그대로 둔다. [저장]은 습득물 상세(A-05)로 간다.
- 저장·업로드 실패: "저장하지 못했어요. 잠시 후 다시 시도해 주세요." / "사진을 올리지 못했어요. 다시 시도해 주세요."
- 빠른 등록 토글은 FL-016(컷 가능)에서 만든다.

### A-04 습득물 목록·검색

- 상단: 검색창 "어떤 물건을 찾으세요? 예) 검은 이어폰 은색 키링", 필터 (상태, 분류, 기간)
- 표 (태블릿) / 카드 (모바일): 썸네일, 분류, 공개 설명, 습득일, 보관 위치, 상태 배지, 후보 n
- 검색 결과는 의미가 비슷한 순. 결과 없음: "비슷한 습득물이 없어요. 분실 신고를 대신 접수할까요?" → A-07
- 빈 상태: A-02와 같음.
- 수만 건 기준: 50건씩 페이지 넘김, 최신순 기본 정렬. 검색을 먼저 쓰게 검색창을 맨 위에 둔다.
- 상단 탭: 전체 / **확인 필요** (빠른 등록에서 AI 확신도가 낮았거나 민감 물품인 것) / 분석 중

### A-05 습득물 상세

- 왼쪽: 사진 (크게, 넘겨보기)
- 오른쪽: 상태 배지, 모든 정보 (비공개 특징 포함), [수정]
- 매칭 후보 섹션: 신고 요약, 유사도, 신고일, 상태. 후보를 누르면 신고 상세(서랍)
- 처리 이력: 시간순 (등록, AI 분석, 매칭, 확인 요청, 승인, 반환…)
- 액션: [반환 처리] (A-09), [경찰 이관], [폐기 처리] — 이관·폐기는 확인 대화상자

### A-06 소유권 확인 요청

- 목록: 요청 시각, 습득물 분류·썸네일, 분실자 이름(있으면), 대기 시간
- 상세 (3단 비교) ★ 핵심: 소유권 확인 화면
  - 왼쪽 "분실자가 말한 것": 신고 원문, 나만 아는 특징, 확인 질문별 답변, 첨부 사진(물건이 나온 여행 사진 포함, 보조 근거), "잘 모르겠어요"로 답한 항목, 연락처
  - 가운데 "AI 비교 (참고용)": 항목별 결과 배지 (일치 / 불일치 / 확인 안 됨), 한 줄 의견, "판단 근거 부족" 표시. 항목: 겉모습 특징, 개인 표시, 내용물, 분실 장소·시간, 일련번호
  - 오른쪽 "보관 중인 물건": 사진, 공개 설명, **비공개 특징 (강조)**, 이 분류의 필수 증빙 (고가품·지갑·신분증)
  - 경고: 같은 습득물에 다른 요청 n건 / 같은 연락처의 최근 확인 요청 n건
  - 정보 부족 안내: 분실자가 "잘 모르겠어요"를 많이 골랐거나 정보 충족도가 낮으면 "정보 부족: 추가 증빙 권장" (`01-prd.md` F7-10)
  - 버튼: **[승인]** (수령 안내 메모, 지참 증빙 자동 채움), [추가 증빙 요청] (요청 내용 입력), [보류] (내부 메모), [거절] (내부 메모)
  - AI 결과가 "일치"여도 승인은 관리자가 직접 누른다.
- 승인 후: "수령 안내를 보냈어요." 이후 반환 처리는 A-09.
- 분실자에게는 AI 비교 결과, 거절 사유, 비공개 특징이 보이지 않는다.

### A-07 분실 신고 목록·대리 신고

- 상단 검색: "연락처로 찾기" (전화번호 뒷자리 4개 또는 이메일). 전화 문의를 받으면 가장 먼저 쓰는 칸이다.
- 목록: 신고일, 설명 첫 줄, 분실 기간, 상태, 후보 수, 접수 경로 (QR/대리), **같은 분 신고 n건** 배지, 문의 n회
- 같은 연락처의 신고는 한 묶음으로 접어서 보여준다. 펼치면 각 신고가 보인다.
- 신고를 누르면 오른쪽 서랍: 신고 내용, 후보, **문의 기록 타임라인** (언제, 누가, 어떤 채널로, 메모), 버튼 [문의 기록] [신고 링크 복사]
- [대리 신고 접수]: P-03과 같은 항목을 한 화면에. 완료 후 신고 링크를 보여주고 [복사] (전화로 불러주거나 문자로 보냄)
- 문구: 검색 칸 "전화번호 뒷자리 4개 또는 이메일", 잘못된 입력 "전화번호 뒷자리 4개나 전화번호 전체, 이메일로 찾을 수 있어요.", 결과 없음 "이 연락처로 받은 신고가 없어요. 대리 신고로 접수할까요?" → [대리 신고 접수], 빈 상태 "아직 분실 신고가 없어요. 시설 페이지 링크를 알리면 분실자가 직접 신고해요."
- 관리자 화면의 신고 상태 배지: 찾는 중(`open`) / 확인 요청 중(`claimed`) / 반환 완료(`resolved`) / 종료(`closed`). 분실자 화면(P-04)의 문구와 다르다.
- 대리 신고: 동의 체크 아래 "분실자에게 위 내용을 알리고 동의를 받았을 때 체크해 주세요." 완료 화면 "신고를 접수했어요." · "전화로 불러주거나 문자로 보내 주세요." · [분실 신고 목록으로]
- 서랍: 설명 정리(AI)가 실패한 신고는 "설명 정리에 실패해서 원문으로 비교했어요." + [다시 분석]. 후보를 누르면 습득물 상세(A-05)로 간다. [문의 기록] 입력은 FL-026(✂️)에서 붙이고, 지금은 기록이 있으면 타임라인만 보여준다

### A-08 시설 설정·QR

- 시설 이름, 지역·주소, 종류, 소개 한 줄, 연락처, 운영 시간, 수령 안내 문구, 구역 목록 (추가·삭제·순서), 보관 기한(일, 기본 30일 · 스키장 365일)
- 공개 페이지: 시설 페이지 주소 [복사], 잇츠미 검색·검색엔진 노출 동의 체크(`is_listed`)
- (P1) QR 영역: QR 미리보기, [PNG 내려받기], [A4 포스터 PDF]. 현장 보조 수단
- 알리기 영역: 홈페이지 "분실물 찾기" 메뉴용 링크, 예약 안내 문자용 문구, 전화 응대용 한 줄을 각각 [복사]. 포스터 붙일 곳 권장: 안내데스크, 출입구, 매표소·리프트권 판매소
- 포스터 문구: "물건을 잃어버리셨나요? / 주우셨나요? QR을 찍어주세요." 아래 한 줄: "찾았는지 궁금하면 전화 대신 신고 링크에서 확인하세요."

### A-09 반환 처리 (모달)

- 수령인 이름 (필수), 확인 방법 (신분증 확인 / 특징 문답 / 잠금 해제 / 일련번호 / 구매 내역 / 기타), 메모. 고가품·지갑·신분증은 잠금 해제, 일련번호, 신분증 확인 중 하나를 꼭 고른다
- 연결된 신고가 있으면 자동 선택, 없으면 "신고 없이 반환" (방문 문의로 바로 돌려준 경우)
- 버튼: **[반환 완료]** → 토스트 "반환 완료했어요."

### A-10 문의 기록 (모달) — 반복 문의 줄이기

- 목적: 전화·방문 문의를 10초 안에 남기고, 다른 직원이 같은 분을 다시 응대할 때 바로 보이게 한다.
- 항목: 채널 (전화 / 방문 / 메시지 / 기타, 기본값 전화), 연결할 신고 (연락처나 설명으로 검색, 고르지 않아도 됨), 연락처 (신고를 고르지 않았을 때), 메모 (한 줄)
- 응대자와 시각은 자동으로 들어간다.
- 버튼: **[기록]** → 토스트 "문의를 기록했어요." 연결한 신고가 있으면 [신고 링크 복사]도 함께 보인다.
- 검색 결과 없음: "이 연락처로 들어온 신고가 없어요. 대리 신고를 접수할까요?" → A-07 대리 신고
