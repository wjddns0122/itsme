## 1. 이번 단계의 목표

**3일 안에 실제 물건 30~50개로 돌아가는 MVP를 만들고, 측정한 수치로 PSST 발표를 완성한다.**

데모가 끝났을 때 아래 다섯 가지를 보여줄 수 있어야 한다.

1. 관리자가 사진 한 장으로 습득물을 등록한다 (AI가 양식을 채운다).
2. 분실자가 QR로 들어와 로그인 없이 자연어로 신고한다.
3. 시스템이 비슷한 습득물 후보를 찾아 보여준다.
4. 분실자가 "내 물건 같아요"를 누르면 관리자가 비공개 특징으로 확인하고 반환 처리한다.
5. 실측 수치: 등록 시간, 신고 시간, Top-3 재현율, 오매칭률 (표본 수 포함).

## 4. 디자인 ↔ 개발 협업 규칙

1. **개발은 디자인을 기다리지 않는다.** Day 1~2 오전까지는 shadcn/ui 기본 스타일로 만든다. 디자인이 오면 토큰(색·폰트·둥글기)부터 적용한다.
2. Figma 프레임 이름 = 화면 ID (`A-03 습득물 등록`). `03-screens.md`의 ID와 같아야 한다.
3. B는 화면마다 **빈 상태·로딩·에러** 세 가지를 함께 그린다.
4. 전달 단위는 "화면 하나 완성"이다. 전체가 끝날 때까지 모았다가 한꺼번에 주지 않는다.
5. 문구는 `03-screens.md`에 적힌 문구가 기준이다. 바꾸고 싶으면 문서를 고친다.

## 8. AI로 개발하는 방법

1. Claude Code 세션을 시작하면 `CLAUDE.md`가 자동으로 읽힌다.
2. 티켓 하나씩 맡긴다: `/ticket FL-011`. 명령이 티켓의 참고 문서를 읽고, 계획을 말하고, 구현 후 `pnpm check`와 수용 기준 체크까지 한다.
3. 결과를 수용 기준으로 직접 확인한다. 커밋 전에 `/review-diff`로 코드 리뷰·보안 점검을 받는다.
4. 결과가 괜찮으면 커밋한다 (`FL-011: ...`).
5. AI가 문서에 없는 규칙을 만들려고 하면 멈추고 `07-decisions.md`에 질문으로 남긴다.
6. 여러 티켓이 끝나면 `/sync-docs`로 코드와 문서가 어긋난 곳을 맞춘다.

Claude Code 설정 전체 구조는 `CLAUDE.md` §9.
