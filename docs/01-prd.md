## 1. 배경과 문제

### 1-1. 근거 자료

- 전국 평균 습득물 반환율 약 35%, 울산경찰청은 적극적 관리로 57% 이상 (연합뉴스 2026-04-14 보도, 팀 조사 자료).
- 휘닉스 평창 블루캐니언 워터파크는 카카오톡 분실물 센터를 따로 운영한다 → 시설마다 접수 채널이 다르다.
- 평창군 자체의 분실 건수·반환율은 아직 확보하지 못했다 (`확인 필요`, 시설 인터뷰로 보완).

> 반환율이 낮다는 사실만으로 기존 시스템의 문제라고 단정하지 않는다. 아래 가설을 설문·인터뷰·MVP로 검증한다.

### 1-2. 이해관계자별 문제

| 이해관계자 | 문제 |
|---|---|
| 분실자 | 어디에 문의해야 할지 모른다. 들렀던 시설마다 전화를 반복한다. 여행지에서 잃어버리면 다시 가기 어렵다. |
| 습득자 | 물건을 어디에 맡겨야 할지 모른다. |
| 시설 관리자 | 습득물 기록·보관을 수기나 엑셀로 한다. 같은 문의 전화에 반복해서 응대한다. 물건을 직접 꺼내 비교해야 한다. |
| 시설 운영사 | 반환 여부와 처리 현황을 파악하기 어렵다. 경찰 이관 기한을 놓칠 수 있다. |

### 1-3. 검증할 가설

| ID | 가설 | 검증 방법 | 성공 기준 (초기값) |
|---|---|---|---|
| H1 | 분실자는 탐색에 1시간 이상 쓰거나 포기한다 | 설문 Q3·Q4 | 응답자의 50% 이상 |
| H2 | 관리자는 습득물 1건 처리(기록+문의 응대)에 10분 이상 쓴다 | 관리자 인터뷰·관찰 | 인터뷰 3곳 이상에서 확인 |
| H3 | 사진 1장 AI 등록이 기존 등록보다 빠르다 | MVP 실측 | 건당 15초 이내 |
| H4 | 자연어 설명으로 정답 습득물을 상위 3개 안에 찾는다 | 평가셋 | Top-3 재현율 90% 이상 |
| H5 | 시설은 월 구독료를 낼 의향이 있다 | 관리자 인터뷰 | MVP 범위 밖, 질문만 수집 |

## 2. 목표와 비목표

### 목표 (MVP)

1. 관리자가 습득물을 **사진 한 장으로 15초 안에** 등록한다.
2. 분실자가 **앱 설치·회원가입 없이 60초 안에** 신고한다.
3. 신고와 습득물을 **자동으로 비교해 후보를 추천**하고, 새 습득물이 들어와도 다시 검색할 필요가 없다.
4. **관리자 승인을 거친 반환**까지 기록이 남는다.

### 비목표 (이번에 하지 않음)

- 결제·구독 기능
- 네이티브 앱
- AI의 소유권 자동 확정
- LOST112 시스템 연동
- 문자·카카오 알림톡 (이메일만)
- 습득자가 직접 습득물을 등록하는 기능
- 여러 시설 통합 검색 (P1)

## 3. 사용자와 페르소나

> 아래 수치는 모두 가정이다. 인터뷰로 고친다.

| 페르소나 | 상황 | 원하는 것 | 불편 |
|---|---|---|---|
| **관광객 분실자** (20대, 서울 거주) | 평창 스키장에서 고글을 잃어버린 걸 집에 와서 알았다 | 다시 가지 않고 찾고 싶다 | 어디에 전화할지 모름, 전화가 안 됨 |
| **대학생 분실자** (인덕대 재학생) | 강의실에 무선 이어폰을 두고 나왔다 | 빨리 찾고 싶다 | 경비실·학과사무실·학생지원센터 중 어디인지 모름 |
| **스키장 안내데스크 직원** | 주말 하루 습득물 20~40건, 문의 전화 다수 | 기록을 빨리 끝내고 문의 응대를 줄이고 싶다 | 수기 장부, 물건 직접 찾기 |
| **학교 관리 담당자** (학생지원센터 조교) | 습득물을 엑셀과 보관함으로 관리 | 손이 덜 가는 관리 | 학생이 와서 물으면 같이 뒤져야 함 |
| **습득자** | 복도에서 지갑을 주웠다 | 어디 맡길지 알고 싶다 | 안내가 없음 |

## 5. 기능 요구사항

> 각 기능의 화면은 `03-screens.md`, 흐름은 `02-user-flows.md`, 데이터는 `04-architecture.md` 참고.

### F1. 시설과 관리자

| ID | 요구사항 |
|---|---|
| F1-1 | 관리자는 이메일·비밀번호로 로그인한다. MVP에서는 회원가입 화면 없이 시드 스크립트로 계정과 시설을 만든다. |
| F1-2 | 관리자는 자기가 속한 시설의 데이터만 본다. |
| F1-3 | 시설 설정: 이름, 구역 목록(예: 안내데스크, 리프트 A), 연락처, 수령 안내 문구, 보관 기한(일). |
| F1-4 | 시설별 QR 코드(신고 페이지 주소)를 PNG로 내려받는다. P0 컷 가능 항목: A4 포스터 PDF. |

### F2. AI 습득물 자동 등록

| ID | 요구사항 |
|---|---|
| F2-1 | 관리자가 사진을 찍거나 고르면(1~3장) AI가 분류, 세부 종류, 색상, 브랜드 후보, 특징을 추출해 양식을 채운다. |
| F2-2 | AI는 특징을 **공개 설명**(분실자에게 보여도 되는 것)과 **비공개 식별 특징**(소유권 확인용)으로 나눈다. |
| F2-3 | 신분증·카드·학생증으로 판단하면 민감 물품으로 표시하고, 이름·번호를 마스킹한다. |
| F2-4 | 관리자는 모든 필드를 고칠 수 있다. 습득 일시(기본값: 지금), 습득 구역, 보관 위치를 입력한다. |
| F2-5 | AI가 실패해도(시간 초과, 파싱 실패) 빈 양식으로 수동 등록할 수 있다. |
| F2-6 | 등록 시작부터 저장까지 걸린 시간을 기록한다 (지표 측정용). |

**수용 기준**: 사진 선택 후 AI 결과가 양식에 채워지기까지 p95 8초 이내. 저장 후 목록에 바로 보인다.

### F3. 습득물 관리

| ID | 요구사항 |
|---|---|
| F3-1 | 목록: 사진 썸네일, 분류, 공개 설명, 습득일, 보관 위치, 상태, 매칭 후보 수. |
| F3-2 | 필터: 상태, 분류, 기간. 정렬: 최신순. |
| F3-3 | 상세: 사진, 전체 정보, 매칭 후보 목록, 처리 이력, 상태 변경(이관·폐기). |
| F3-4 | 자연어 검색: "검은 이어폰 은색 키링"을 입력하면 의미가 비슷한 순으로 보여준다. |

### F4. 분실 신고

| ID | 요구사항 |
|---|---|
| F4-1 | 분실자는 시설 QR(`/f/{slug}`)로 들어와 로그인 없이 신고한다. |
| F4-2 | 1단계 "무엇을": 자유 서술(필수, 10자 이상), 분류 선택(선택). |
| F4-3 | 2단계 "언제·어디서": 분실 기간(시작일~종료일, 기본값 오늘), 구역(시설 구역 목록 + "잘 모르겠어요"). |
| F4-4 | 3단계 "연락처·확인": 이메일 또는 전화번호 중 하나 이상(필수), 이름(선택), **나만 아는 특징**(선택, 비공개), 개인정보 수집·이용 동의(필수). |
| F4-5 | 제출하면 바로 신고 링크(`/r/{token}`)를 보여주고, 이메일이 있으면 링크를 보낸다. AI 분석은 응답 후 백그라운드에서 한다. |
| F4-6 | 관리자 대리 신고: 전화 문의를 받은 관리자가 같은 양식으로 신고를 대신 접수한다. |

**수용 기준**: 신고 제출 응답 1초 이내. 제출 후 30초 안에 신고 현황 페이지에 매칭 결과가 반영된다.

### F5. 자동 매칭

| ID | 요구사항 |
|---|---|
| F5-1 | 신고가 들어오면 같은 시설의 보관 중 습득물과 비교한다. |
| F5-2 | 습득물이 새로 등록되면 같은 시설의 진행 중인 신고와 비교한다 (역방향). |
| F5-3 | 점수 = 물품 특징 60% + 장소 25% + 날짜 15%. 계산식은 `05-ai-matching.md` §5. |
| F5-4 | 점수 0.45 이상을 신고당 최대 5개까지 후보로 저장한다. |
| F5-5 | 점수는 "소유 확률"이 아니다. 화면에는 숫자 대신 "유사도 높음 / 보통"으로 보여준다. |

### F6. 신고 현황과 알림

| ID | 요구사항 |
|---|---|
| F6-1 | 신고 링크로 들어오면 신고 내용 요약, 상태, 후보 목록을 본다. |
| F6-2 | 후보 카드에는 분류, 공개 설명, 습득일, 시설·구역만 보인다. **사진과 비공개 특징은 보이지 않는다.** |
| F6-3 | 점수 0.70 이상의 새 후보가 생기면 이메일로 알린다 (신고 1건당 하루 최대 3통). |
| F6-4 | 분실자는 후보에 "내 물건이 아니에요"를 눌러 숨길 수 있다. |
| F6-5 | 분실자는 신고를 취소할 수 있다. |

### F7. 소유권 확인과 반환

| ID | 요구사항 |
|---|---|
| F7-1 | 분실자는 후보에 "내 물건 같아요"를 누르고, 공개 설명에 없는 특징을 적어 소유권 확인을 요청한다 (사진 첨부 선택). |
| F7-2 | 관리자는 요청 화면에서 분실자의 설명·답변과 습득물 사진·비공개 특징을 나란히 보고 승인 또는 거절한다. |
| F7-3 | 승인하면 분실자에게 수령 안내(장소, 시간, 지참물)를 보여주고 이메일로 보낸다. |
| F7-4 | 관리자가 물건을 건네고 "반환 완료"를 누르면 수령인 이름, 확인 방법, 메모를 기록한다. |
| F7-5 | 한 습득물이 반환되면 그 습득물의 다른 후보는 모두 자동으로 정리된다. |
| F7-6 | 모든 상태 변경은 처리 이력에 남는다. |

### F8. 대시보드

| ID | 요구사항 |
|---|---|
| F8-1 | KPI: 보관 중 습득물 수, 검토 대기 중인 소유권 확인 요청 수, 이번 달 반환 수, 이번 달 반환율. |
| F8-2 | 할 일: 검토 대기 요청, 이관 기한 3일 이내 습득물. |
| F8-3 | (컷 가능) 최근 7일 습득·반환 막대 차트. |

반환율 정의: `이번 달 등록된 습득물 중 반환 완료 수 / 이번 달 등록된 습득물 수`.

## 6. 비기능 요구사항

| 분류 | 요구사항 |
|---|---|
| 성능 | 사진 분석 p95 8초 이내. 신고 제출 응답 1초 이내. 목록 첫 화면 2초 이내. |
| 보안 | 관리자 데이터는 RLS로 시설 단위 격리. 사진은 비공개 저장소 + 10분 만료 서명 URL. 신고 링크 토큰은 추측 불가(192비트). |
| 개인정보 | 최소 수집(연락처 1개 필수, 이름 선택). 수집 목적·보관 기간을 동의 문구에 명시. 신고 종료 후 30일 안에 연락처 삭제(MVP는 수동, P1 자동). 연락처는 LLM에 보내지 않음. 민감 물품 사진 비공개. |
| 접근성 | 글자 대비 4.5:1 이상, 터치 영역 44px 이상, 모든 입력에 라벨. |
| 호환성 | 모바일 Safari·Chrome 최신 2개 버전, 데스크톱 Chrome. |
| 신뢰성 | AI 실패 시 수동 입력으로 계속 진행. 매칭 실패는 재시도 가능. |
| 비용 | 데모 기간에는 무료 요금제 안에서 운영 (Supabase Free, Vercel Hobby). AI 호출 비용은 건당 기록. |

## 7. 성공 지표 (MVP 실증 목표)

> 목표치는 결과가 아니다. 실측값은 측정일과 표본 수를 함께 적는다.

| 지표 | 목표 | 측정 방법 |
|---|---|---|
| 습득물 등록 소요시간 | 15초 이내 (중앙값) | `register_started_at` ~ 저장 시각 |
| 분실 신고 소요시간 | 60초 이내 (중앙값) | `report_started_at` ~ 제출 시각 |
| Top-3 재현율 | 90% 이상 | 평가셋 (`05-ai-matching.md` §7) |
| 오알림률 | 10% 이하 | 등록 안 된 물건의 신고가 알림 기준을 넘은 비율 |
| 관리자 업무시간 감소 | 50% 이상 | 기존 방식 vs FindLink, 같은 물건 10개로 비교 |
| 사용자 만족도 | 5점 중 4점 이상 | 사용성 테스트 후 설문 |

## 8. 가정과 리스크

- 시설 관리자가 사진 촬영에 협조한다고 가정한다.
- 분실자가 신고 링크를 저장하거나 이메일을 입력한다고 가정한다 (계정이 없으므로 링크를 잃으면 접근 불가 → 이메일 재발송 기능 P1).
- 유실물법상 시설 점유자의 경찰 제출 의무와 기한은 `확인 필요`. 보관 기한은 시설 설정값으로 두고 기본 7일로 시작한다.
- 리스크 대응은 `00-plan.md` §6.

## 9. 경쟁과 차별화

AI 매칭 자체는 차별점이 아니다 (파인딩올, NotLost, Nuvlost가 이미 제공). MVP에서 검증할 차별화 가설:

| 차별화 | MVP에서 보여줄 것 |
|---|---|
| 도입 편의성 | QR 코드 하나로 시작, 설치 없음 |
| 고객 접근성 | 앱 설치·회원가입 없는 신고 |
| 관리 편의성 | 사진 한 장 등록, 문의 응대용 자연어 검색 |
| 관광 특화 | (P1) 다국어 신고, 택배 반환 |
| 행정 연계 | (P1) 이관 기한 관리 |

LOST112를 대체하지 않는다. 개별 시설의 현장 관리 업무를 보완한다.
