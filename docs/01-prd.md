## 1. 배경과 문제

### 1-1. 근거 자료

- 전국 평균 습득물 반환율 약 35%, 울산경찰청은 적극적 관리로 57% 이상 (연합뉴스 2026-04-14 보도, 팀 조사 자료).
- 휘닉스 평창 블루캐니언 워터파크는 카카오톡 분실물 센터를 따로 운영한다 → 시설마다 접수 채널이 다르다.
- 평창군 자체의 분실 건수·반환율은 아직 확보하지 못했다 (`확인 필요`, 시설 인터뷰로 보완).

> 반환율이 낮다는 사실만으로 기존 시스템의 문제라고 단정하지 않는다. 아래 가설을 설문·인터뷰·MVP로 검증한다.

### 1-2. 현장 인터뷰 결과 (2026-11-25, 4곳)

인덕대학교 학과 사무실, 학생처, 도서관과 스키장 1곳의 담당자에게 직접 물었다.

> 아래 수치는 손글씨 메모를 옮긴 것이다. 관리 방식과 기간의 정확한 의미는 인터뷰한 팀원에게 다시 확인한다 (Q12). 특히 "처리 시간"과 "보관 기간"을 나눠서 다시 묻는다.

| 항목 | 학과 사무실 | 학생처 | 도서관 | 스키장 |
|---|---|---|---|---|
| 습득물 발생량 | 월 10개 | 주 3~4건 | 시험기간 10개 | 하루 수십~100건 |
| 관리 방식 | 학생처·학과 관리 | 보관 및 안내 | 1층 경비실·사무실 | 별도 바구니 보관 |
| 분실물 문의 | 월 10건 | 월 10건 이상 | 거의 없음 | 습득물보다 문의가 훨씬 많음 |
| 처리·보관 기간 | 다양함 | 당일~1달 | 1개월~1개월 반 | 1년 보관 |
| 가장 큰 불편 | 분실물 처리 업무 | 체계적인 데이터 관리 부재 | 공지해도 찾아가지 않음 | 반복 문의로 다른 업무에 집중하기 어려움 |

발견한 문제
1. **데이터 관리 부재**: 무엇이 어디에 있는지 체계적인 기록이 없다 (학생처).
2. **반복 문의**: 한 사람이 여러 번 묻거나, 여러 직원에게 따로 묻는다 (스키장).
3. **장기 보관 부담**: 공지해도 찾아가지 않고, 스키장은 1년을 보관한다.
4. **본업 방해**: 문의 응대 때문에 다른 업무에 집중하기 어렵다 (스키장).

2번과 4번이 가장 강한 사업화 근거다. 시설이 돈을 낼 이유를 "업무시간 절감"으로 설명할 수 있다.

> 현장에서 확인된 문제는 위 네 가지다. 잘못된 반환, 직원이 등록을 안 하는 문제, 같은 물건 여러 개, 서비스를 모르는 문제, 집에 돌아간 관광객, 기억 부족은 운영을 가정해 도출한 위험이며 아직 현장 검증 전이다 (§11).

### 1-3. 문제 정의 (인터뷰 후 수정)

| | 내용 |
|---|---|
| 이전 | 분실자가 잃어버린 물건을 찾기 어렵다. |
| **지금** | 시설마다 흩어진 비체계적인 분실물 관리와 반복 문의 때문에 관리자의 업무 부담이 커지고, 반환 과정이 비효율적이다. |

또한 사진과 설명만 보고 돌려주면 남의 물건을 자기 것이라고 주장하는 **잘못된 반환**이 생길 수 있다. 현장 인터뷰에서 확인된 사례는 아니지만(Q13), 발표·피드백에서 가장 많이 받은 질문이다.

핵심 메시지: **분실물은 찾아주고, 관리 업무는 줄여주는 AI SaaS.** 차별점은 발견부터 소유권 확인, 안전한 반환까지 한 흐름으로 관리하는 것이다.

세 기둥: **빠른 등록**(관리자 업무 감소) · **자동 탐색**(반복 문의 감소) · **안전한 반환**(잘못된 반환 방지). 설계 원칙: **검색은 관대하게, 반환은 엄격하게** (ADR-020).

포지셔닝 (v0.5): **장소 기반 AI 분실물 통합 탐색 및 시설 관리 SaaS.** QR은 보조 수단이다. 집에 돌아간 관광객은 QR을 찍을 수 없고, 결국 시설에 전화해 접속 방법을 물어야 하기 때문이다. 핵심 UX 원칙: **한 번만 신고하면, 이후에는 직접 문의하지 않아도 시스템이 알아서 물건을 찾아준다** (ADR-026).

| | 분실자가 하는 일 |
|---|---|
| 이전 | 분실 인지 → 방문 장소 기억 → 시설마다 전화번호 검색 → 시설마다 전화 → 직원이 확인 → 못 찾으면 다시 전화 |
| 잇츠미 | 분실 인지 → 방문한 시설 검색·선택 → 한 번만 신고 → AI가 계속 찾고 알림 → 소유권 확인 후 반환 |

### 1-4. 이해관계자별 문제

| 이해관계자 | 문제 |
|---|---|
| 분실자 | 어디에 문의해야 할지 모른다. 들렀던 시설마다 전화를 반복한다. 여행지에서 잃어버리면 다시 가기 어렵다. |
| 습득자 | 물건을 어디에 맡겨야 할지 모른다. |
| 시설 관리자 | 습득물 기록·보관을 수기나 엑셀로 한다. 같은 문의 전화에 반복해서 응대한다. 물건을 직접 꺼내 비교해야 한다. |
| 시설 운영사 | 반환 여부와 처리 현황을 파악하기 어렵다. 경찰 이관 기한을 놓칠 수 있다. |

## 2. 목표와 비목표

### 목표 (MVP)

1. 관리자가 습득물을 **사진 한 장으로 15초 안에** 등록한다. 빠른 등록 모드에서는 관리자 조작 5초.
2. 분실자가 **앱 설치·회원가입 없이 60초 안에** 신고한다.
3. 신고와 습득물을 **자동으로 비교해 후보를 추천**하고, 새 습득물이 들어와도 다시 검색할 필요가 없다.
4. **잘못된 반환을 막는다.** 매칭(AI)과 소유권 확인(사람 + AI 보조)을 나누고, 관리자 승인과 기록을 거쳐서만 반환한다.
5. **반복 문의를 줄인다.** 분실자는 신고 링크로 스스로 현황을 보고, 관리자는 같은 사람의 여러 신고·문의를 한 묶음으로 본다.
6. **기억이 흐려도 찾을 수 있게 한다.** 모르는 항목은 "잘 모르겠어요"로 넘기고, 모른다고 답한 항목은 점수에서 불이익을 주지 않는다.
7. **어디서든 시작할 수 있게 한다.** 현장 QR이 없어도 시설 이름·지역으로 검색해서 신고한다. 집에 돌아간 뒤에도 마찬가지다.

### 비목표 (이번에 하지 않음)

- 결제·구독 기능
- 네이티브 앱
- AI의 소유권 자동 확정
- LOST112 시스템 연동
- 문자·카카오 알림톡 (이메일만)
- 습득자가 직접 습득물을 등록하는 기능
- 여러 시설 통합 검색 (P1)

## 3. 사용자와 페르소나

> 스키장·학교 수치는 2026-11-25 인터뷰 기준이고, 나머지는 가정이다. 대학교는 MVP 테스트 장소, 스키장은 첫 사업화 대상이다 (ADR-016).

| 페르소나 | 상황 | 원하는 것 | 불편 |
|---|---|---|---|
| **관광객 분실자** (20대, 서울 거주) | 평창 스키장에서 고글을 잃어버린 걸 집에 와서 알았다 | 다시 가지 않고 찾고 싶다 | 어디에 전화할지 모름, 전화가 안 됨 |
| **대학생 분실자** (인덕대 재학생) | 강의실에 무선 이어폰을 두고 나왔다 | 빨리 찾고 싶다 | 경비실·학과사무실·학생지원센터 중 어디인지 모름 |

| F1-2 | 관리자는 자기가 속한 시설의 데이터만 본다. |
| F1-3 | 시설 설정: 이름, 구역 목록(예: 안내데스크, 리프트 A), 연락처, 수령 안내 문구, 보관 기한(일). |
| F1-4 | (P1) 시설별 QR 코드 PNG와 A4 포스터. 현장 보조 수단이다 (ADR-026). |
| F1-5 | 분실자가 서비스를 알게 하는 길: 시설 홈페이지 "분실물 찾기" 메뉴, 예약 안내 문자, 전화 응대에 붙여 쓸 전용 링크와 짧은 안내 문구를 [복사]로 제공한다. 포스터 권장 위치: 안내데스크, 출입구, 매표소·리프트권 판매소. |
| F1-6 | 시설 공개 페이지(`/f/{slug}`): 시설이 동의하면(`is_listed`) 잇츠미 시설 검색과 검색엔진에 노출한다. 페이지 제목 "{시설 이름} 분실물 찾기 \| 잇츠미". |

### F2. AI 습득물 자동 등록

| ID | 요구사항 |
|---|---|
| F2-1 | 관리자가 사진을 찍거나 고르면(1~3장) AI가 분류, 세부 종류, 색상, 브랜드 후보, 특징을 추출해 양식을 채운다. |
| F2-2 | AI는 특징을 **공개 설명**(분실자에게 보여도 되는 것)과 **비공개 식별 특징**(소유권 확인용)으로 나눈다. |
| F2-3 | 신분증·카드·학생증으로 판단하면 민감 물품으로 표시하고, 이름·번호를 마스킹한다. |
| F2-4 | 관리자는 모든 필드를 고칠 수 있다. 습득 일시(기본값: 지금), 습득 구역, 보관 위치를 입력한다. |
| F2-5 | AI가 실패해도(시간 초과, 파싱 실패) 빈 양식으로 수동 등록할 수 있다. |
| F2-6 | 등록 시작부터 저장까지 걸린 시간을 기록한다 (지표 측정용). |
| F2-7 | **빠른 등록 모드**: 사진 → 보관 위치(직전 값) → 저장만 하고 바로 다음 촬영. AI 분석은 백그라운드에서 하고, 확신도가 낮거나 민감 물품이면 "확인 필요" 목록으로 보낸다. |
| F2-8 | **민감 물품 버튼**: 신분증·카드는 AI 분석 없이 분류만 골라 등록한다. 사진을 외부 AI로 보내지 않는다. |

**수용 기준**: 사진 선택 후 AI 결과가 양식에 채워지기까지 p95 8초 이내. 저장 후 목록에 바로 보인다. 빠른 등록 모드는 관리자 조작 5초 이내 (AI 대기 제외).

### F4. 분실 신고

| ID | 요구사항 |
|---|---|
| F4-1 | 분실자는 잇츠미에서 시설을 검색하거나(시설 이름·지역·종류), 검색엔진·시설 홈페이지 링크·현장 QR로 시설 페이지(`/f/{slug}`)에 들어와 로그인 없이 신고한다. |
| F4-2 | 1단계 "무엇을": 분류 선택, 색상(모르면 "잘 모르겠어요"), 브랜드(모르면 "잘 모르겠어요"), 자유 서술(선택). 분류나 설명 중 하나만 있어도 된다. |
| F4-3 | 2단계 "언제·어디서": 분실 기간(시작일~종료일, 기본값 오늘), 마지막으로 쓴 시간대(오전/점심/오후/저녁/모름), 구역(시설 구역 목록 + "잘 모르겠어요"), 대여한 물건인지 체크. |
| F4-4 | 3단계 "연락처·확인": 이메일 또는 전화번호 중 하나 이상(필수), 이름(선택), **나만 아는 특징**(선택, 비공개), 개인정보 수집·이용 동의(필수). |
| F4-5 | 제출하면 바로 신고 링크(`/r/{token}`)를 보여주고, 이메일이 있으면 링크를 보낸다. AI 분석은 응답 후 백그라운드에서 한다. |
| F4-6 | 관리자 대리 신고: 전화 문의를 받은 관리자가 같은 양식으로 신고를 대신 접수한다. |
| F4-7 | **내 사진으로 찾기**: 여행 중 찍은 사진처럼 물건이 나온 사진을 올리면 AI가 물건 특징을 뽑아 신고에 더한다. 사진은 보조 근거일 뿐 소유 증명이 아니다. |
| F4-8 | "잘 모르겠어요"는 틀린 답이 아니다. 모르는 항목은 저장하지 않고(null), 점수에서 빼고 계산한다 (F5-3). |
| F4-9 | 신고 후에도 신고 링크에서 내용을 보완할 수 있다. 보완하면 다시 매칭한다. |

**수용 기준**: 신고 제출 응답 1초 이내. 제출 후 30초 안에 신고 현황 페이지에 매칭 결과가 반영된다.

### F5. 자동 매칭

| ID | 요구사항 |
|---|---|
| F5-1 | 신고가 들어오면 같은 시설의 보관 중 습득물과 비교한다. |
| F5-2 | 습득물이 새로 등록되면 같은 시설의 진행 중인 신고와 비교한다 (역방향). |
| F5-3 | 점수 = 물품 특징 60% + 장소 25% + 날짜 15%. 분실자가 모르는 항목은 0점이 아니라 계산에서 빼고(동적 가중치), 실제로 비교한 항목의 비중을 **정보 충족도**로 따로 낸다. 계산식은 `05-ai-matching.md` §5. |
| F5-4 | 점수 0.45 이상을 신고당 최대 5개까지 후보로 저장한다. |
| F5-5 | 점수는 "소유 확률"이 아니다. 화면에는 숫자 대신 "유사도 높음 / 보통"으로 보여준다. |
| F5-6 | 비슷한 물건이 여러 개면(상위 후보 점수 차 0.05 이내) 하나를 고르지 않고 모두 보여준다. 구별은 소유권 확인 단계에서 한다. |
| F5-7 | 정보 충족도가 낮으면 후보는 보여주되 "정보가 적어요"를 표시하고 알림은 보내지 않는다. |

### F6. 신고 현황과 알림

| ID | 요구사항 |
|---|---|
| F6-1 | 신고 링크로 들어오면 신고 내용 요약, 상태, 후보 목록을 본다. |
| F6-2 | 후보 카드에는 대표 사진 1장, 분류, 공개 설명, 습득일, 시설·구역이 보인다. **비공개 특징은 보이지 않는다.** 민감 물품, 지갑·카드·서류, AI 확인 전이거나 검토가 필요한 물건은 사진 없이 분류 아이콘만 (ADR-030). |
| F6-3 | 점수 0.70 이상이고 정보 충족도 0.65 이상인 새 후보가 생기면 이메일로 알린다 (신고 1건당 하루 최대 3통). 신고 뒤에 들어온 습득물도 자동으로 비교한다 (F5-2). |
| F6-4 | 분실자는 후보에 "내 물건이 아니에요"를 눌러 숨길 수 있다. |
| F6-5 | 분실자는 신고를 취소할 수 있다. |

### F7. 소유권 확인과 반환

원칙: **AI 매칭과 소유권 확인을 분리한다.** 매칭은 "비슷한 물건"을 찾을 뿐이고, 주인인지는 비공개 정보로 따로 확인한다. AI는 확인을 돕기만 하고 결정은 관리자가 한다 (ADR-007, ADR-019).

| ID | 요구사항 |
|---|---|
| F7-1 | 분실자가 후보에 "내 물건 같아요"를 누르면 **분류별 확인 질문 2~3개**에 주관식으로 답한다 (`05-ai-matching.md` §9-1). 질문은 그 분류의 모든 물건에 똑같이 나간다. 질문만 보고 이 물건에 어떤 비공개 특징이 있는지 알 수 없게 하기 위해서다. 사진 첨부는 선택. |
| F7-2 | 서버는 답변과 습득물의 비공개 특징을 AI로 비교해 항목별 결과(일치 / 불일치 / 확인 안 됨)와 한 줄 의견을 만든다. 이 결과는 **관리자에게만** 보인다. |
| F7-3 | 분류마다 확인 수준이 있다. 고가품(휴대폰, 노트북·태블릿, 스마트워치)과 지갑·카드·신분증은 답변이 맞아도 수령 때 추가 증빙(잠금 해제, 일련번호, 신분증)을 확인해야 반환할 수 있다. |
| F7-4 | 관리자는 A-06에서 분실자 답변, AI 비교 결과, 습득물 사진·비공개 특징을 나란히 보고 **승인 / 추가 증빙 요청 / 보류 / 거절** 중 하나를 고른다. |
| F7-5 | 추가 증빙 요청: 관리자가 필요한 증빙(예: "구매 내역 사진", "케이스 안쪽 사진")을 적으면 분실자의 신고 링크에 요청이 보이고, 분실자가 답하면 다시 검토 대기로 돌아온다. |
| F7-6 | 시도 제한: 한 신고에서 동시에 확인 요청은 1건, 같은 습득물에는 같은 신고로 최대 2번까지 요청할 수 있다. 같은 연락처(F9-1)로 7일 안에 서로 다른 습득물 3건 이상을 요청하면 관리자 화면에 경고한다. |
| F7-7 | 승인하면 수령 안내(장소, 시간, 지참할 증빙)를 보여주고 이메일로 보낸다. |
| F7-8 | 관리자가 물건을 건네고 "반환 완료"를 누르면 수령인 이름, 확인 방법, 메모를 기록한다. 한 습득물이 반환되면 그 습득물의 다른 후보는 자동으로 정리된다. 모든 상태 변경은 처리 이력에 남는다. |
| F7-9 | 특징이 없는 흔한 물건(비닐우산, 무지 장갑 등)은 이 방법으로도 확실히 판단하기 어렵다. AI 비교 결과에 "판단 근거 부족"을 표시하고, 관리자가 보류하거나 직접 확인한다. |
| F7-10 | 기억 수준과 물건의 위험도에 따라 확인을 달리한다 (아래 표). 분실자가 올린 사진은 보조 근거일 뿐, 사진에 나왔다는 것만으로 반환하지 않는다. |

**하지 않는 것**: AI의 자동 승인, 자체 모델 학습, 제조사 일련번호 조회 API 연동.

**수용 기준**: 같은 분류의 습득물 두 개에 나가는 확인 질문이 똑같다. AI 비교 결과와 비공개 특징은 분실자 응답과 이메일에 없다 (테스트). 고가품은 수령 안내에 지참할 증빙이 표시된다.

확인 수준 (검색은 관대하게, 반환은 엄격하게)

| 분실자 상태 | 확인 방법 |
|---|---|
| 고유 특징을 기억함 | 확인 질문 답변을 비공개 특징과 비교 |
| 대략적인 겉모습만 기억함 | 시간·장소로 후보를 찾고, 확인 질문 + 관리자 확인 |
| 겉모습은 모르지만 물건이 나온 사진이 있음 | 사진을 보조 근거로 보고 추가 확인 |
| 거의 기억하지 못함 | 구매 내역 등 추가 증빙 요청 |
| 아무 증빙이 없음 | 관리자 직접 확인 또는 반환 보류 |

고가품(휴대폰, 노트북·태블릿, 스마트워치)과 지갑·신분증은 기준을 높이고, 증빙이 부족하면 보류한다.

### F9. 반복 문의 줄이기 (인터뷰 후 추가)

스키장 인터뷰에서 가장 큰 불편은 "같은 사람이 여러 번, 여러 직원에게 문의한다"였다.

| ID | 요구사항 |
|---|---|
| F9-1 | 신고를 저장할 때 연락처를 정규화한 키(`contact_key`: 전화번호 숫자만 또는 소문자 이메일)를 만든다. 같은 시설에서 같은 키를 가진 진행 중 신고는 관리자 화면에서 "같은 분 신고 n건"으로 묶어 보여준다. |
| F9-2 | 관리자는 전화·방문 문의를 받으면 [문의 기록] 한 번으로 채널, 연결할 신고, 메모를 남긴다. 응대자와 시각은 자동. 신고 상세에 문의 기록이 시간순으로 보인다. 신고 없이도 기록할 수 있다. |
| F9-3 | (P1) 연락처가 달라도 설명·기간이 거의 같은 신고를 중복 후보로 표시한다. |
| F9-4 | 관리자는 연락처(전화번호 뒷자리 4개 또는 이메일)로 기존 신고를 찾는다. 찾으면 상태를 안내하고 신고 링크를 다시 알려준다. |
| F9-5 | 시설 QR 포스터와 신고 완료 화면에 "진행 상황은 전화하지 않고 이 링크에서 확인할 수 있어요" 안내를 넣는다. |

**개인정보 규칙**: 분실자에게는 묶였다는 사실이나 같은 연락처의 다른 신고를 절대 보여주지 않는다. 남의 전화번호를 입력해 그 사람의 신고가 있는지 알 수 있으면 안 되기 때문이다.

**수용 기준**: 같은 전화번호로 신고 2건을 넣으면 관리자 목록에 한 묶음으로 보인다. 분실자 화면 응답에는 다른 신고 정보가 없다 (테스트). 문의 기록은 10초 안에 남길 수 있다.

### F10. 반환 방법 (관광객 대응)

관광객은 집에 돌아간 뒤에 분실을 알아채는 경우가 많고, 물건을 찾아도 다시 오기 어렵다.

| ID | 방법 | 우선순위 | 내용 |
|---|---|---|---|
| F10-1 | 방문 수령 | P0 | 승인 때 수령 장소·운영 시간·지참 증빙 안내 (F7-7) |
| F10-2 | 수령 일정 예약 | P1 | 분실자가 방문 날짜·시간대를 고른다 |
| F10-3 | 대리 수령 | P1 | 대리인 이름·관계 입력, 본인 확인 질문 통과 + 대리인 신분증 확인. 고가품은 대리 수령 불가 |
| F10-4 | 착불 택배 | P1 | 분실자가 주소를 입력하고, 관리자가 발송 완료·송장번호를 기록한다. 주소는 반환 후 30일 안에 삭제. 택배사 연동은 P2 |
| F10-5 | 경찰 이관 안내 | P1 | 보관 기한이 지나 이관한 물건은 신고 링크에 이관 기관과 날짜를 보여준다 |

### F11. 장소 기반 탐색 (시설 검색이 기본 입구)

QR만으로는 이미 집에 돌아간 사람이 신고할 수 없다. 결국 시설에 전화해 접속 방법을 물어야 하고, 반복 문의를 줄인다는 핵심 가치가 약해진다. 그래서 시설 검색을 기본 입구로 하고 QR은 보조로 둔다 (ADR-026).

| ID | 요구사항 | 우선순위 |
|---|---|---|
| F11-1 | 시설 찾기: 시설 이름·지역으로 검색하고 종류(스키장, 숙박·리조트, 대학교 등)로 거른다. 결과에서 시설 페이지로 간다 | P0 |
| F11-2 | 미참여 시설 안내: 찾는 시설이 없으면 "아직 잇츠미를 쓰지 않아요. 시설에 직접 문의하거나 LOST112에서 찾아보세요"를 보여준다 | P0 |
| F11-3 | 진입 경로 4가지: 검색엔진(시설 페이지, F1-6), 시설 공식 홈페이지 "분실물 찾기" 메뉴(F1-5), 잇츠미 직접 접속(F11-1), 현장 QR(F1-4, P1). 어디로 들어와도 같은 시설 페이지에서 시작한다 | P0 (QR은 P1) |
| F11-4 | 여러 시설 한 번에 신고: 어디서 잃어버렸는지 모를 때 방문한 시설 여러 곳을 골라 한 번에 신고한다. 시설마다 신고가 따로 만들어지고 그 시설 관리자에게만 전달된다. 분실자는 링크 하나로 모두 본다 | P1 |
| F11-5 | 지역 기반 통합 탐색: 시설 자체를 모르면 지역(예: 평창군)의 참여 시설 전체에 신고한다 | P1 |
| F11-6 | 지도에서 시설 찾기 | P2 |
| F11-7 | 방문 기록 연동: 예약·결제 기록에서 방문한 시설을 자동으로 제안 | P2 |

시설 상태별 안내

| 상태 | 분실자에게 보여줄 것 |
|---|---|
| 참여 시설 · 후보 있음 | 소유권 확인 진행 (F7) |
| 참여 시설 · 후보 없음 | 새 습득물이 등록되면 자동 알림 (F6-3) |
| 미참여 시설 | 기존 분실물 문의 채널과 LOST112 안내 (F11-2) |
| 시설 자체를 모름 | (P1) 지역 기반 참여 시설 통합 탐색 (F11-5) |

데모 시설과 시안에는 실제 상호 대신 예시 이름을 쓴다. 실제 시설 이름은 제휴가 확정된 뒤에만 쓴다 (ADR-028).

## 8. 가정과 리스크

- 시설 관리자가 사진 촬영에 협조한다고 가정한다.
- 분실자가 신고 링크를 저장하거나 이메일을 입력한다고 가정한다 (계정이 없으므로 링크를 잃으면 접근 불가 → 이메일 재발송 기능 P1).
- 유실물법상 시설 점유자의 경찰 제출 의무와 기한은 `확인 필요` (Q2, 팀원 C). 인터뷰상 실제 보관 기간은 시설마다 크게 다르다 (학생처 당일~1달, 도서관 1~1.5개월, 스키장 1년). 보관 기한은 시설 설정값으로 두고 기본 30일, 스키장은 365일로 시작한다 (ADR-018).
- 허위 소유권 주장은 현장 인터뷰에서 확인되지 않았다. 발표·피드백에서 가장 많이 받은 질문이라 MVP에 넣고, 스키장 추가 인터뷰에서 사례를 묻는다 (Q13).
- 리스크 대응은 `00-plan.md` §6.

## 9. 경쟁과 차별화

AI 매칭 자체는 차별점이 아니다 (파인딩올, NotLost, Nuvlost가 이미 제공). MVP에서 검증할 차별화 가설:

| 차별화 | MVP에서 보여줄 것 |
|---|---|
| 도입 편의성 | 시설 등록만 하면 전용 페이지·링크가 생긴다. 홈페이지·안내 문자에 링크만 넣으면 된다 (QR은 보조) |
| 고객 접근성 | 앱 설치·회원가입 없이, 현장이 아니어도 시설 검색으로 신고 |
| 관리 편의성 | 사진 한 장 등록, 문의 응대용 자연어 검색 |
| 반복 문의 감소 | 같은 분 신고 묶기, 문의 기록, 셀프 현황 조회 (F9) |
| 안전한 반환 | 매칭과 소유권 확인 분리, 정답을 드러내지 않는 확인 질문, AI 답변 비교, 고가품 추가 증빙 (F7) |
| 네트워크 | 참여 시설이 늘수록 한 번의 신고로 찾을 수 있는 범위가 넓어진다 (F11-4, F11-5) |
| 관광 특화 | (P1) 다국어 신고, 택배 반환 |
| 행정 연계 | (P1) 이관 기한 관리 |

LOST112를 대체하지 않는다. 개별 시설의 현장 관리 업무를 보완한다.

| 비교 | LOST112 | 잇츠미 |
|---|---|---|
| 목적 | 국가 유실물 통합 관리 | 시설 운영 업무 줄이기 |
| 핵심 고객 | 국민, 유실물 취급기관 | 스키장·리조트 등 시설 운영자 |
| 핵심 가치 | 유실물 신고·탐색 | 빠른 등록, 반복 문의 감소, 안전한 반환 |
| 사업 모델 | 공공 서비스 | 시설별 B2B 구독 |
| 관계 | 공공 유실물 시스템 | 보완하고 경찰 이관을 돕는다 |

이 표는 포지셔닝 차이다. LOST112에 해당 기능이 없다고 단정하지 않는다. 실제 기능 중복은 팀원 C가 조사한다.

## 11. 발표 예상 질문과 답

| 예상 질문 | 답 | 근거 |
|---|---|---|
| 남의 물건을 가져가면요? | 매칭과 소유권 확인을 나눈다. 분류별 확인 질문, AI 답변 비교, 관리자 승인, 고가품 추가 증빙 | F7 |
| AI가 잘못 판단하면요? | AI는 후보를 보여줄 뿐 결정하지 않는다. 근거가 부족하면 "판단 근거 부족"으로 보류 | F5-5, F7-9 |
| 똑같은 물건이 여러 개면요? | 시간·장소·특징을 함께 본다. 점수가 비슷하면 하나를 고르지 않고 확인 단계에서 가린다 | F5-6 |
| 직원이 등록을 안 하면요? | 사진 한 장 등록, 빠른 등록 모드 관리자 조작 5초. 등록하면 문의 응대가 준다 | F2-7, F9 |
| 사람들이 서비스를 어떻게 알죠? | 검색엔진에 뜨는 시설 페이지, 시설 홈페이지 "분실물 찾기" 메뉴, 잇츠미에서 시설 검색, 예약 안내 문자, 현장 QR(보조) | F1-5, F1-6, F11 |
| 가입 안 한 시설에서 잃어버리면요? | 그 시설의 습득물은 찾을 수 없다. 기존 문의 채널과 LOST112를 안내하고, 참여 시설이 늘수록 해결된다 | F11-2 |
| LOST112와 뭐가 다르죠? | 공공 통합 관리가 아니라 시설 현장 업무(등록·문의·반환)를 줄이는 B2B 도구. 이관을 돕는 보완 관계 | §9 |
| 개인정보가 새면요? | 민감 물품은 AI 분석 생략·사진 비공개, 연락처는 AI에 안 보냄, 30일 후 삭제 | F2-8, §6 |
| 기억이 안 나면요? | 모르는 항목은 넘겨도 불이익이 없고, 물건이 나온 사진으로도 찾는다. 대신 반환은 엄격하게 | F4-7, F4-8, F7-10 |
| 관광객이 이미 집에 갔으면요? | QR 없이 시설 검색으로 집에서 신고한다. 수령은 MVP는 방문, 수령 예약·대리 수령·착불 택배는 다음 단계 | F11, F10 |
| 시설이 돈을 낼까요? | 업무시간 절감으로 증명한다. 스키장 문의 건수·응대 시간을 재고 시연으로 도입 의향을 확인 | §7, Q9, Q11 |
| 특허로 보호되나요? | 선행기술 조사 중. 후보: 비공개 특징 기반 확인 보조, 동적 가중치와 정보 충족도 분리 등 | `00-plan.md` §2 |
| 스키장 비수기에는요? | 리조트·워터파크·축제·대학으로 넓힌다 | `00-plan.md` §7 |
| 왜 임베딩·LangChain을 안 쓰나요? | MVP 규모(시설당 하루 최대 100건, 2주 창)에서는 SQL로 후보를 줄인 뒤 Gemini가 직접 비교하는 편이 빠르게 만들고 이유도 설명된다. 데이터가 쌓이면 임베딩 검색(Stage 2)과 LangChain 파이프라인(Stage 3)으로 넓힌다 | `05-ai-matching.md` §10, ADR-023 |

현장에서 확인된 근거와 가정을 섞어 말하지 않는다. 현장 근거는 §1-2의 네 가지다.
