# 프롬프트·매칭 값 변경 절차

바꾸는 이유를 한 문장으로 먼저 적는다. (예: "검은 이어폰끼리 오매칭이 많아 색상 가중치를 낮춘다")

## 1. 기준값
- 평가 데이터(`eval/cases.json`)가 있으면, 바꾸기 전에 `pnpm eval`로 기준 결과를 남긴다.
- `pnpm eval`은 실제 API 비용이 든다. 실행 전에 사람에게 확인받는다.
- 평가 데이터가 아직 없으면 그 사실을 보고에 적고 진행한다.

## 2. 변경
- 프롬프트: `src/lib/ai/prompts.ts`
- 출력 스키마·분류·색상: `src/lib/validation/`
- 가중치·임계값: 매칭 설정 파일과 `.env.example`
- 관련 단위 테스트를 함께 고친다 (`pnpm test`).

## 3. 평가
- 같은 조건으로 `pnpm eval`을 다시 돌린다.
- **dev 분할 결과만 보고** 판단한다. test 분할은 발표용 최종 확인에만 쓴다 (`docs/05-ai-matching.md` §7-5).
- 비교 표: Top-3 재현율, 오알림률, 분류 정확도, 사진 분석 p95, 건당 비용.

## 4. 기록
- `docs/05-ai-matching.md`의 해당 섹션(§2~§5)을 새 값으로 고친다.
- §10 변경 기록에 `날짜 | 변경 | 근거(전후 수치, 표본 수)`를 추가한다.
- 모델을 바꿨으면 `docs/07-decisions.md` ADR-009를 갱신한다.
- 임베딩 모델·차원을 바꿨으면 ADR-008 갱신 + 재임베딩 계획 + `COS_LOW/HIGH` 재보정.
