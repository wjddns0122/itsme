# 매칭 평가 데이터 모으기 (팀원용 한 장)

기준 문서: `docs/05-ai-matching.md` §7. 목표 수치는 `docs/01-prd.md` §7.

## 무엇을 모으나

| 묶음 | 개수 | 하는 일 |
|---|---|---|
| 실제 물건 (습득물) | 30~50개 | 팀원·지인의 물건. 사진 1~3장 |
| 비슷한 물건 묶음 | 4묶음 이상 | 검은 무선 이어폰 3개, 검은 장갑 2켤레, 흰 충전기 3개, 비슷한 카드지갑 2개 |
| 정답 있는 신고 | 물건마다 1건 | 주인이 사진을 보지 않고 기억대로 60초 안에 쓴 설명 |
| 미끼 신고 | 10건 | 등록하지 않은 물건의 설명. 높은 후보가 나오면 안 된다 |
| 중복 신고 | 3쌍 | 같은 사람이 같은 물건을 표현만 바꿔 두 번 |
| 기억이 흐린 신고 | 10건 | 분류·구역·날짜만, 설명은 비움 |
| 소유권 확인 답변 | 진짜 10건 + 가짜 10건 | 진짜는 주인이, 가짜는 다른 팀원이 공개 정보만 보고 답한다 |

## 순서

1. 주인이 물건을 맡기기 **전에** 사진을 보지 않고 설명을 쓴다 (실제 분실자처럼, 60초).
2. 다른 사람이 관리자 역할로 사진을 찍는다. 사진은 `eval/photos/I01-1.jpg`처럼 저장한다.
3. 습득물마다 사람이 정답 분류·색상을 적는다 (`truth`).
4. 분실 날짜·구역은 실제 사람처럼 가끔 하루 틀리거나 비워 둔다 (`null`).
5. 신고를 `dev`와 `test` 반반으로 나눈다. 가중치·프롬프트는 `dev`만 보고 고치고, 발표에는 `test`를 쓴다.

## 지켜야 할 것

- 사진에 사람 얼굴, 이름, 학번, 카드번호, 주소가 나오지 않게 가리거나 다시 찍는다. 신분증·카드는 평가에 넣지 않는다.
- 설명·답변에 실제 연락처를 쓰지 않는다. 평가 스크립트는 `@example.invalid` 주소를 쓴다.
- 무료 등급 Gemini 키로는 이렇게 팀이 만든 데이터만 보낸다 (ADR-025).

## 파일 형식 (`eval/cases.json`)

`eval/cases.example.json`을 복사해서 쓴다. 필드는 `docs/05-ai-matching.md` §7-2와 같다. 신고에 `user_category`(P-03 칩 값)를 넣을 수 있다.

## 실행

```bash
pnpm eval
```

- 실제 API 비용이 든다. 사람이 정해서 돌린다 (`CLAUDE.md` §7).
- 평가 전용 시설을 만들고 끝나면 지운다. 남기려면 `EVAL_KEEP=1 pnpm eval`.
- 결과는 `eval/results/YYYY-MM-DD.md`. 숫자에는 표본 수와 날짜를 같이 적는다.
